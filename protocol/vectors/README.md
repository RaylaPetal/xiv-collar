# Cross-Runtime Test Vectors

`crypto-vectors.json` is generated by a Node WebCrypto reference script (the
same primitives Cloudflare Workers expose) and self-verified at generation
time: the ECDSA signature is checked against its public key, and the AES-GCM
ciphertext is decrypted back to the original plaintext using the
independently-derived Owner-side key. That proves the vector is internally
consistent; it does not yet prove interoperability with .NET or the Worker
runtime, because neither exists yet in this repository.

Consumers, added in later tasks:

- **Worker test suite** (task 2.1/8.1): import `canonicalJson`, re-derive the
  digest, verify `ecdsaSignRequest.signatureBase64Url` against
  `signingPublicKeyJwk` using WebCrypto, and re-run the AES-GCM
  encrypt/decrypt using `ecdhHkdfAesGcmCatalogEnvelope`'s fixed keys/nonce and
  assert byte-identical ciphertext and matching plaintext.
- **Plugin test suite** (task 3.3/8.2): import the same JWKs and fixed
  nonce/salt/info into `System.Security.Cryptography.ECDsa` /
  `ECDiffieHellman`, reproduce the same canonical JSON digest, verify the same
  signature, derive the same AES key via `HKDF.DeriveKey`, and decrypt the
  same ciphertext to the same plaintext.

Only when both suites pass against this file does task 1.2 verification
criterion ("published cross-runtime vectors pass in both C# and Worker
tests") hold; regenerating `crypto-vectors.json` (see `../../scripts` once
added, or re-run the generation script) is required if `constants.json`
changes.
