## Why

Three independent, verified gaps:

1. **The Owner has no way to learn what aliases a Sub set up.** Title/Outfit/Gesture/Restraint aliases (`config.Aliases.*`) are Sub-local convenience words the Sub types into their own catalog - `AliasBook.cs` explicitly documents that "the Owner only ever needs to know the alias name... never these definitions," and `collar/chat-transport`'s own "Alias resolution against a locally-defined dictionary" requirement already says only the alias's short name should ever cross to the Owner, never what it does. But today there's no mechanism at all for that name to reach the Owner except the Sub reading it out loud - catalog-sync's existing unified export only covers scanned catalogs (Wardrobe designs, Gesture animations, Moodles statuses, Restraint devices), never the aliases layered on top of them. The Owner's general "Alias / one-off" box (`DrawFreeformComposer`) already exists specifically to send a raw alias word, but the Owner has to already know it to type it.
2. **The Owner's Title quick-command has no color or prefix control**, even though `collar/title`'s own spec already promises "text, and optionally color/glow/prefix-suffix." `TitleCommand.ForceApply(string text)`'s own doc comment admits the gap: "No prefix/color control yet - defaults to a plain white suffix." The Sub's own Title alias UI (`DrawTitleModule`) already has a working `ColorEdit3` and prefix checkbox feeding `TitleAliasDefinition.Color`/`IsPrefix` - the Owner's quick-command path (`DrawTitleQuickSection`) just never got the same treatment, and neither did the underlying `ForceApply` method or the `title create <text>` wire grammar.
3. **A Sub's Scan & Export file can exceed 10MB**, verified to come almost entirely from Gesture: `GestureCommand.ExportCatalog()` serializes every playable catalog entry's *full* `GestureCatalogEntry` (including `GroupSelections`, a dictionary that redundantly repeats every other option group's current selection state on every single entry) as JSON, then base64-encodes it. This scales combinatorially (entries × other-groups-in-the-same-mod), not linearly with catalog size. Confirmed by tracing the importer (`CatalogSyncService.ImportGestureLines`): it only ever reads `Id`, `ModName`, `GroupName`, `GroupOrder`, `OptionOrder`, and the computed `Label` (which needs `AnimationName`/`Trigger`) - `GroupSelections`, `ModDirectory`, `TriggerOrder`, and `ModEnabled` are exported but never consumed by the Owner side at all. They're only meaningful to the Sub's own client, which already has them locally in `GestureMapping.LocalCatalog` and never needs them re-imported - `GestureCommand.Execute`'s temporary Penumbra activation reads `GroupSelections` straight off the Sub's own local catalog entry, looked up by `Id`, regardless of anything the Owner ever sent.

## What Changes

- **Sub can export their per-item aliases; Owner can import them as one-off quick commands.** Scan & Export gains a new section listing every alias word (deduplicated) from the Title, Outfit, Gesture, and Restraint alias lists - names only, never what each alias maps to, preserving the existing "opaque to the Owner" design principle. Importing populates the Owner's general "Alias / one-off" list with one quick command per alias word (`Command` = the alias itself, sent exactly as if the Owner had typed it into that box). **Scope note**: Follow's engage/release words and the two singleton Clear-title/Unlock-outfit aliases are excluded - the Owner already has dedicated fixed quick-command rows for all of those, so exporting them here would be redundant.
- **Owner's Title quick-command gains a prefix checkbox and color picker**, matching the Sub's own Title alias UI exactly. `TitleCommand.ForceApply` gains prefix/color parameters (no more hard-coded plain white). The wire grammar adds a **new, distinct sub-verb** (`title style "<text>" ...`) alongside the existing plain `title create <text>` rather than appending a suffix to `create` itself - title text is arbitrary free text with no catalog to match against (unlike a restraint device name), so an old client can't distinguish "extra text" from "a suffix it doesn't understand" the way the restraint/pairing wire formats already fail closed; a genuinely new, unshared verb token is the only way an old client's exact-prefix dispatch cleanly falls through to "unrecognized" instead of appending the color/prefix syntax onto the visible title text. Existing saved quick commands using plain `create` are completely unaffected.
- **Gesture's exported payload drops everything the Owner-side importer never reads**: `GroupSelections`, `ModDirectory`, `TriggerOrder`, and `ModEnabled` are no longer serialized into the export line - only `Id`, `ModName`, `AnimationName`, `GroupName`, `GroupOrder`, `OptionOrder`, and `Trigger` (needed for the existing playable-trigger filter and the computed `Label`) are. The Sub's own local catalog and gesture-playing behavior are completely unaffected - this only trims what leaves the Sub's machine in the export file, not what's used to actually play a gesture.

## Capabilities

### Modified Capabilities
- `collar/catalog-sync`: adds a Sub alias-name export/import section; shrinks the Gesture export payload to only Owner-importer-needed fields.
- `collar/title`: the Owner's title command (both the quick-command UI and the underlying wire command) now actually carries prefix/color, closing the gap the spec already described but the implementation never delivered.

## Impact

- `CollarSystem.Plugin/Commands/CatalogSyncService.cs` - new `## ALIASES` export section (built from `config.Aliases.Titles/Outfits/Gestures/Restraints`) and its import path into `config.QuickCommands.Aliases`; `GestureCommand.ExportCatalog`'s serialized payload shrinks to the fields above.
- `CollarSystem.Plugin/Commands/GestureCommand.cs` - export serializes a slimmed payload instead of the full `GestureCatalogEntry`; local catalog storage and `Execute`/gesture-playing behavior unchanged.
- `CollarSystem.Plugin/UI/CollarWindow.cs` - `DrawTitleQuickSection` gains a prefix checkbox + `ColorEdit3`, mirroring `DrawTitleModule`'s existing controls.
- `CollarSystem.Plugin/Commands/TitleCommand.cs` - `ForceApply` gains `isPrefix`/`color` parameters.
- `CollarSystem.Plugin/Commands/ChatCommandListener.cs` - `HandleForceTitle` gains a new `style` sub-verb branch (checked alongside `clear`/`create`) parsing the quoted text plus prefix/color; `create` itself is untouched.
- `CollarSystem.Plugin/Config/PluginConfig.cs` - `QuickCommand` gains `TitleIsPrefix`/`TitleColor` fields (mirroring the existing `GestureModName`-style "kept in sync with the encoded command" pattern already used for Restraints/Gesture).
- **No breaking change**: the alias-export section, the new `title style` verb, and the Gesture export trim are all purely additive - existing `title create` quick commands, existing exported/imported files, and Gesture playback are all unaffected. **Known limitation, not a regression**: an Owner on this version paired with a Sub still on an older one will find `title style` silently rejected as "unrecognized" by that Sub (same as any command from a category the Sub's older client doesn't understand yet) rather than applying a plain-white fallback - consistent with this plugin's existing convention that wire-format additions assume both sides update together (see the trigger-phrase auto-sync precedent in the README).
